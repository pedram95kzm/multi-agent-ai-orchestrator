# Verification and limitations

- `npm run format:check` checks source formatting; generated outputs and the exact protocol text are excluded.
- `npm run typecheck` covers the desktop app, extension, shared connection types, orchestration, and tests, including unused local variables and parameters.
- `npm test` checks protocol/counters, inline and Markdown Summary formats, exact command review, task chat assignments, cross-task isolation, cascading task deletion, migration, persistence, operating-system capture, explicit role sends, the minimal task tools, collapsed message views, code toolbar actions, four DOM adapters, authenticated bridge behavior, and real Bash execution including conditional `&&` chains. Native PowerShell tests run when its executable is available and cover stdout/stderr, UTF-8, working directory, native exit codes, and terminating errors.
- `npm run build` builds the Electron app, renderer, and unpacked Chrome extension.
- Desktop service tests verify trusted-frame and clipboard checks, validated IPC, role-aware manual counter adoption, rejection of removed onboarding actions, instruction validation/backups, and preservation of conversation evidence.
- Extension ownership regressions cover a new task using a different URL in a previously assigned tab, preserved pending evidence and original-URL reconnection, genuine active-task conflicts, orphaned cached assignments, cancelled and concurrent connection attempts, scoped pairing caches, same-token pending-delivery preservation, and startup restoration races. The real browser smoke navigates an existing task tab to a fresh URL, binds it to a new task without sending, and pairs again with the same token without producing an ownership error.
- Manual handover regressions cover all three buttons, Watcher-only authorship, Operator recipients, project-only output without added protocol/role assignment, and both replacement roles, verbatim protocol and report copying, exact requirements, independent counters, original response 1, actual execution evidence, cross-task isolation, editable URLs, no automatic send, stale batch withdrawal, atomic refusal during execution, and retirement of legacy staged workflows without replay. Both roles acknowledge the manual packet without incrementing their checkpoint, then answer their first real handoff at the next number without receiving duplicate agent.md. Receipt evidence survives recovery; missing, stale, wrong-role, wrong-task, wrong-counter or command-bearing receipts do not establish protocol delivery. A protocol change requires updated instructions.
- Handoff regressions cover direct Watcher approval to Operator, exact code, shell and directory matching, legacy approval-loop recovery, versioned delivery-rule updates for existing chats and retries, PowerShell approval, missing-question answer fields, and rejection of historical proposal recovery without confirmed briefing and delivery evidence. Renderer tests verify automatic output filling only after completion, all terminal statuses, preservation of other answers and subsequent edits, result copying, blocked execution, and explicit answer submission.
- Directory-revision tests cover an identical batch resubmitted with corrected metadata, confirmed delivery to the same Watcher, retirement of older unreviewed revisions, and rejection of edited code, different shells/Actors, older directories, uncertain delivery and duplicate corrections. An explicit local recheck can repair the latest saved directory-conflict review while preserving message bodies, counters and execution approval. Startup does not grant that permission. The browser smoke forwards a corrected proposal and verifies that only it becomes ready, without running it.
- Execution regressions verify that Watcher-authored Bash and PowerShell batches can change files with user approval, that both roles use the same execution policy, and that approval remains mandatory alongside shared command safeguards.
- PowerShell formatting regressions allow `Format-Table` and `Format-List` for both batch origins and capture their real output in a temporary test directory. Disk-formatting executables and other destructive or privileged commands remain blocked.
- Nested-fence capture tests cover all four providers with Markdown references containing three- and four-backtick examples followed by a separate PowerShell file-writing batch. Reference questions and summaries remain literal. The real Chrome smoke captures such a reference while executing only the approved inspection. Saved-capture refresh tests require the same role, counters, URLs, exact code and directory and confirmed original deliveries; they reject changed/stale replies without partial mutation and preserve original captures without sends or execution.
- Task-start regressions verify that the first message goes to the Watcher, Actor sending remains disabled until confirmed delivery, failed or uncertain sends do not unlock it, and the rule persists across recovery and Watcher replacement without leaking between tasks. UI and core also block handovers before the first Watcher submission and Actor replacement before its first response. The packaged smoke checks those disabled controls and starts each task through the Watcher button before enabling Actor sends.
- Operator-reply regressions cover both senders, fixed reply targets, confirmed delivery, uncertain retries, restart recovery, stale forms and task isolation. Ordinary questions remain mandatory; generated handover documents do not require acknowledgment. Historical directory and repeated-question examples in reports do not create metadata notices or answer fields.
- Context-health regressions cover footer attachment to every outbound kind and retry, fence-aware status parsing, contradictory or missing status, role and counter validation, initial and replacement baselines, persistent warnings through restart, alerts across task views, simple role-specific onboarding suggestions without actions, and preservation of counters and historical response 1. The smoke test checks the actual delivered footer, simulates loss for both roles, observes their alerts, and verifies that replacements clear those recommendations.
- DeepSeek capture regressions cover sibling syntax tokens, mixed code and span elements, explicit line breaks, line wrappers, exact Windows paths, whitespace, hidden controls, and parsing the complete captured command batch. A nested first-token regression preserves an entire PowerShell file-writing example through its Python and Markdown contents and verification, while taking the shell language from the outer banner instead of an inner SQL token. The packaged smoke test captures and executes an inspection with a nested first token and the remaining command text in sibling spans.
- Capture-correlation regressions cover merged old/new assistant wrappers, nested wrappers, stale greetings, assigned roles, expected numbers, wrong chat URLs, rejected acknowledgment, restart inspection without resending, and blocked forwarding of ignored captures. First-delivery regressions cover saved ready labels, existing counters, full confirmed protocol evidence, and exact current handoff text. The smoke fixture reveals a pre-existing greeting for longer than the stability interval before the real answer arrives; it must not complete a pending delivery. Task A starts its Actor through the Watcher's current handoff and verifies the actual submitted briefing and complete protocol. Verified manual replacements receive the continued message without a duplicate protocol copy.
- `npm run test:smoke` runs the built app and the actual extension in an isolated installed Chrome profile. Controlled fixture documents are served at the supported provider URLs through that test browser's request interception. No account is used and no AI message is sent to a real provider.
- The smoke test covers the task management home page, independent panel minimization and restoration, conversation space at normal and smaller window sizes, draft preservation, automatic URL fields, reusing already-open tabs, exact first-message instructions, explicit role delivery, one Send activation and returned replies for ChatGPT/Qwen/DeepSeek/GLM, emphasized collapsed summaries and full-text expansion, task switching, and cascading deletion. It executes a read-only inspection from the approved message, verifies inline output, verifies all three handover modes, copies the fixed-role complete packets and manually pastes them into both new-role fixture chats, changes their editable URLs, checks role-aware continued counters and absence of any automatic submission, and obtains a complete handover reply.
- `npm run package:win` runs the checks, builds installer and portable outputs, and repeats the smoke test against the portable executable and its bundled extension.

The smoke test also checks syntax-highlighted code, numbered terminal-results answer fields, and the native desktop clipboard copy action. On Windows, an optional independent read of the system clipboard verifies the copied code's exact checksum: set `$env:RELAY_SMOKE_VERIFY_CLIPBOARD = "1"` before running the smoke test. That additional OS clipboard check requires an unlocked interactive desktop; the default integration test can run while Windows is locked. Unit tests separately cover exact copied whitespace, line endings, per-block copy selection, full-message copying, and safe rendering of code containing HTML.

A live DeepSeek acceptance check on 21 October 2026 used the portable app, the unpacked extension, and two existing signed-in chats in the user's regular Chrome profile. A task received a Watcher briefing, passed messages between both roles, recorded an exact command review, created a minimal Python project through Relay's terminal, ran it with exit code 0 and output `Hello, World!`, returned the actual evidence, and received the Watcher's final completion report. This also reproduced and fixed reply capture when DeepSeek reused the same number of DOM elements without message IDs. The pending reply was recovered without resending the prompt. DeepSeek code block language and whitespace were checked against its live page structure.

Fixture tests verify integration but do not certify every current signed-in provider layout. ChatGPT, Qwen, and GLM currently have fixture coverage; this acceptance check did not send live messages to those services. Provider selectors and generation controls can change. Streaming completion uses provider generation controls and stable answer text; ambiguous delivery is surfaced without automatic replay.

The smoke test uses Chrome's isolated extension debugging support. Regular app operation uses the extension in the user's existing Chrome profile and does not enable Chrome remote debugging. Chrome controls extension installation; Load unpacked is a one-time user setup step.

Windows code signing and automatic updates are not configured. Installer publisher prompts remain expected. Approved command execution is not an OS sandbox.
